# 什么是Agent？和大模型有什么本质不同？
要点： 
- 自主性：传统AI是用户提问，然后回答。Agent可以根据提示词去自主规划。
- 能动性：传统AI智能进行文字类回复。Agent可以调用各种工具。

大模型类似于一个问答机器，给一个输入，就会给你一个输出。就算是多轮会话，也是在上下文中被动响应，不会主动去做事。
缺点：
**知识被冻结** 数据容易过期，比如今天的天气，股价。大模型是不知道的，因为训练的时候就没有带上这个数据。
**不能行动** 最多就是写邮件，但是发邮件的事得用户自己去做。
**没有记忆** 每次调用都是独立的，刚说完我叫李刚，下次问大模型我叫什么，大模型还是不知道。

Agent如何改善
Agent Loop： 核心就是一个循环： 感知->规划->行动->再感知
- 工具调用
给Agent提供调用外部工具的拓展能力。
如何解决上面三个问题：`知识冻结：可以通过搜索工具去补充。 不能行动：外部工具可以帮助Agent行动，比如提供发邮件的接口。 没有记忆：上下文存储在外部数据库或者缓存中。通过工具去访问。`
**工具调用的核心**
1. tool_schema 名称，描述，需要的参数(交互格式)。本质上是一份说明书，告诉大模型什么时候用这个东西，怎么用。约定交互的格式。
```
# 这里定义了两个工具，就像给 Agent 配了两个「技能说明书」
# 注意：这里没有一行真正执行的逻辑，只是告诉模型「我有哪些能力、需要哪些参数」
tools = [
    {
        "name": "get_weather",
        "description": "获取指定城市的当前天气",
        "parameters": {
            "type": "object",
            "properties": {
                "city": {"type": "string", "description": "城市名称"}
            },
            "required": ["city"]
        }
    },
    {
        "name": "send_email",
        "description": "发送邮件给指定收件人",
        "parameters": {
            "type": "object",
            "properties": {
                "to": {"type": "string"},
                "subject": {"type": "string"},
                "body": {"type": "string"}
            },
            "required": ["to", "subject", "body"]
        }
    }
]

# 你告诉 Agent："帮我查一下北京天气，然后发邮件给 boss@company.com"
# Agent 不是一次性回答，而是分两步真正执行：
# 第一步：调用 get_weather(city="北京") → 得到 "晴天 15°C"
# 第二步：调用 send_email(to="boss@company.com", subject="今日天气", body="北京今天晴天 15°C")
# 每一步都是真实发生的，不是在"假装"
```
2. 调用工具
LLM根据tool_schema去返回的数据可能是一个json。例如
```
{
  "tool_calls": [
    {
      "id": "call_001",
      "type": "function",
      "function": {
        "name": "send_email",
        "arguments": "{\"to\":\"admin@example.com\",\"subject\":\"告警通知\",\"body\":\"服务器CPU持续过高，请尽快处理\"}"
      }
    }
  ],
  "content": null
}
```
我们需要根据这个json体的内容去调用对应的工具方法。

- 记忆机制
短期记忆：放在内存中的中间计算结果。比如
```
User: 1+1 = ?
LLM: 2
# 需要基于上一次对话的结果 发送给大模型的可能是： 1+1=？ 2 再加1呢？
User: 再加1呢?
LLM：3
```
长期记忆
夸任务的检索，比如用户的喜好，历史记录，通常都是用向量数据库来存储的。
需要的时候语义检索拿回来。
涉及RAG建设

- 多步骤推理和自我纠错
Agent某一步失败的时候，不会直接崩溃，感知和失败，分析原因，换一种方式重试。
比如用A信息没有搜索到，就用B在试一次。调用某个Api报错之后，会查看报错然后调整参数重试。

# Agent的基本架构，有哪些核心组件构成
Agent架构包含4个组件，LLM、工具、记忆、规划模块
LLM是整个系统的大脑，负责理解任务和决策。
工具是让Agent与外界交互探索，执行代码的媒介。
记忆是Agent执行任务中保证状态，不会失忆。
规划模块负责将复杂任务拆分成可执行的步骤。

## LLM核心
Agent的大脑，所有输入，指令，用户记忆，工具结果都需要由LLm来理解和决策。负责判断下一步做什么，继续思考还是调用某个工具。
**输入**： 关键是System Prompt（系统提示词）
