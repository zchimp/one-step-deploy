按照 Go 项目规范重构代码结构，禁止所有逻辑堆在 main.go：
1. 遵循标准 Go 工程布局，单一职责原则拆分文件；
2. main.go 只保留：初始化流程、路由注册、服务启动、信号优雅关闭，不写业务处理函数；
3. 分层拆分：
   - cmd/server/main.go 程序入口
   - handler/ 存放 gin http handler（接口逻辑）
   - service/ 业务逻辑
   - pkg/ 通用工具、健康检查、响应封装
   - config/ 配置加载
4. 包命名全部小写，不要出现循环导入；
5. 拆分完成后修复所有 import，保证代码可直接编译运行；
6. 逐步重构，不要一次性大面积删除代码，改动一处保存一处；
7. 不要合并功能，每个文件职责清晰。


严格要求：
禁止把多个不同职责的函数保留在同一个文件。
凡是 http handler、业务逻辑、工具函数、配置代码必须物理拆分到独立文件。
main 文件只允许做组装、初始化、启动，不实现任何业务功能。
重构完成列出目录树，并且保证代码能正常编译。
如果文件代码量偏大，主动进一步拆分。
