# Kubernetes 1.28.15 升级到 1.29.x 详细操作指南

## 重要提醒

**升级前必须阅读：**

- **禁止跨版本升级**：必须严格按照 1.28 → 1.29 → 1.30 的顺序进行
- **备份是必须的**：升级前必须完整备份 etcd 数据
- **逐节点升级**：Worker 节点必须逐个升级，禁止同时升级多个节点
- **验证是关键**：每完成一个升级步骤后，必须验证集群状态正常

---

## 升级前重要变更说明

### 1.29 版本重大变更

**移除 v1beta2 流控 API**

- `flowcontrol.apiserver.k8s.io/v1beta2` 已被彻底移除
- 必须迁移到 `v1` 或 `v1beta3` 版本

**移除树内云提供商集成**

- Azure、GCE、vSphere 等内置云提供商已移除
- 必须切换到外部云控制器管理器（External CCM）

**CronJob 时区变更**

- `.spec.schedule` 中不再支持 `CRON_TZ` 或 `TZ`
- 需改用 `.spec.timeZone` 字段

## 第一阶段：升级前准备

### 1. 检查集群当前状态

```bash
# 确认当前版本
kubectl version --short

# 检查所有节点是否 Ready
kubectl get nodes

# 检查所有系统 Pod 是否正常
kubectl get pods -A
```

### 2. 备份 etcd（最关键的一步）

```bash
# 创建备份目录
mkdir -p /opt/etcd-backup

sudo apt install -y etcd-client

# 先设置环境变量，指定api版本，后续命令就不用重复写了
export ETCDCTL_API=3

# 执行快照备份
etcdctl snapshot save /opt/etcd-backup/etcd-snapshot-$(date +%Y%m%d).db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key

# 验证备份文件
etcdctl snapshot status /opt/etcd-backup/etcd-snapshot-*.db -w table
# +----------+----------+------------+------------+
# |   HASH   | REVISION | TOTAL KEYS | TOTAL SIZE |
# +----------+----------+------------+------------+
# | 16032eb5 |  2324396 |       1899 |      17 MB |
# +----------+----------+------------+------------+

```

### 3. 备份配置文件

```bash
cp -r /etc/kubernetes /opt/kubernetes-backup/
```

### 4. 检查已弃用的 API

使用 `pluto` 或 `kubent` 工具扫描集群中是否使用了即将被移除的 API：

```bash
# 安装 pluto（如果未安装）
curl -LO https://github.com/FairwindsOps/pluto/releases/download/v5.24.0/pluto_5.24.0_linux_amd64.tar.gz
tar -xzf pluto_linux_amd64.tar.gz
sudo mv pluto /usr/local/bin/
# 然后扫描
pluto detect-api-resources --target-versions k8s=v1.29.0 -o wide
```

### 5. 确认目标版本

```bash
# Ubuntu/Debian
apt-cache madison kubeadm | grep 1.29

# CentOS/RHEL
yum list kubeadm --showduplicates | grep 1.29
```

**建议选择最新的 1.29 补丁版本（如 1.29.15）**

## 第二阶段：升级 Master 节点

### 1. 封锁 Master 节点（禁止调度）

```bash
kubectl cordon <master-node-name>
```

### 2. 排空 Master 节点上的 Pod

```bash
kubectl drain <master-node-name> \
  --delete-emptydir-data \
  --ignore-daemonsets \
  --force
```

### 3. 升级 kubeadm 工具

**Ubuntu/Debian:**

```bash
apt-mark unhold kubeadm
apt-get update
apt-get install -y kubeadm=1.29.15-00
apt-mark hold kubeadm
```

**CentOS/RHEL:**

```bash
yum mark unhold kubeadm
yum install -y kubeadm-1.29.15-0
yum mark hold kubeadm
```

### 4. 查看升级计划

```bash
kubeadm upgrade plan
```

### 5. 查看升级差异（可选但推荐）

```bash
kubeadm upgrade diff v1.29.15
```

### 6. 执行控制平面升级

```bash
kubeadm upgrade apply v1.29.15 --etcd-upgrade=false
```

### 7. 升级 kubelet 和 kubectl

**Ubuntu/Debian:**

```bash
apt-mark unhold kubelet kubectl
apt-get install -y kubelet=1.29.15-00 kubectl=1.29.15-00
apt-mark hold kubelet kubectl
```

**CentOS/RHEL:**

```bash
yum mark unhold kubelet kubectl
yum install -y kubelet-1.29.15-0 kubectl-1.29.15-0
yum mark hold kubelet kubectl
```

### 8. 重启 kubelet

```bash
systemctl daemon-reload
systemctl restart kubelet
```

### 9. 解除 Master 节点封锁

```bash
kubectl uncordon <master-node-name>
```

### 10. 验证 Master 升级结果

```bash
kubectl get nodes
kubectl get pods -A
```

## 第三阶段：逐个升级 Worker 节点

**对每个 Worker 节点重复以下步骤：**

### 1. 封锁节点

```bash
kubectl cordon <worker-node-name>
```

### 2. 排空节点

```bash
kubectl drain <worker-node-name> \
  --delete-emptydir-data \
  --ignore-daemonsets
```

### 3. 升级 kubeadm

```bash
apt-mark unhold kubeadm
apt-get install -y kubeadm=1.29.15-00
apt-mark hold kubeadm
```

### 4. 执行节点升级

```bash
kubeadm upgrade node
```

### 5. 升级 kubelet 和 kubectl

```bash
apt-mark unhold kubelet kubectl
apt-get install -y kubelet=1.29.15-00 kubectl=1.29.15-00
apt-mark hold kubelet kubectl
```

### 6. 重启 kubelet

```bash
systemctl daemon-reload
systemctl restart kubelet
```

### 7. 解除封锁

```bash
kubectl uncordon <worker-node-name>
```

### 8. 验证该节点状态

```bash
kubectl get node <worker-node-name>
```

## 补充建议

### CNI 插件兼容性

- 升级前确认 CNI 插件（Calico/Cilium/Flannel）支持 1.29 版本

### CoreDNS 版本

- kubeadm 会自动升级 CoreDNS
- 如果手动管理 CoreDNS，需要单独确认版本兼容

### 观察窗口

- 每完成一步升级后，建议观察 15-30 分钟再继续下一步

### 回滚方案

- 如果升级失败，使用之前备份的 etcd 快照进行恢复

### 多 Master 架构

- 如果是多 Master 集群，需要逐个升级每个 Master 节点
- 保持至少一个 Master 节点可用

## 升级后注意事项

### 监控指标变更

- 检查监控系统中的指标名称是否发生变化
- 更新相关的告警规则

### RBAC 权限变更

- 检查是否有新的 RBAC 权限要求
- 更新相关的 ServiceAccount 配置

### 插件兼容性

- 确认所有插件和 Operator 支持 1.29 版本
- 特别是存储插件、网络插件等关键组件

## 常见问题处理

### 升级卡住

- 检查 Pod 状态，查看是否有 Pod 无法调度
- 检查节点状态，确认节点是否 Ready
- 查看 kubelet 日志：`journalctl -u kubelet`

### API Server 启动失败

- 检查证书是否过期
- 检查 etcd 连接是否正常
- 查看 API Server 日志：`kubectl logs -n kube-system kube-apiserver-<node-name>`

### Worker 节点无法加入

- 检查 kubelet 配置是否正确
- 确认网络插件是否正常工作
- 查看节点事件：`kubectl describe node <node-name>`

## 总结

**升级成功的关键：**

1. **充分准备**：备份、检查、测试
2. **严格按步骤执行**：不要跳过任何步骤
3. **逐节点升级**：避免同时升级多个节点
4. **全面验证**：每步升级后都要验证
5. **有回滚方案**：确保出现问题时能恢复

升级完成后，建议持续监控集群状态至少 24 小时，确保所有功能正常运行。
