  ## 模块分工

  - alert/ — 告警引擎（eval 评估 → process 构建事件/屏蔽 → queue 队列 → dispatch 派发 → sender 通知）；双通知体系：老 NotifyGroups/Channels + 新 NotifyRuleIds

  - datasource/ — Datasource 接口 (datasource.go:83)，prom/es/ck/mysql/pgsql/tdengine/doris/opensearch/victorialogs 插件
  - dskit/ — 各数据库驱动 + 连接池（全局 pool.PoolClient 缓存连接）
  - dscache/ — 数据源缓存，2s 轮询 DB 同步，center→edge 经 HTTP 下发
  - memsto/ — 内存缓存层（规则/屏蔽/订阅/数据源/target/通知规则/通知渠道/消息模板…），9s 轮询 DB 同步，StatChanged 增量检测

  - integrations/ — 社区贡献的各中间件/数据库监控仪表盘与告警规则

## 三条核心数据流

  - 指标采集转发：Categraf → pushgw/router 解码 → AppendLabels 富化(业务组/target标签) → writer.IdentQueue → WriterType(Prometheus remote write) / KafkaWriterType → 时序库。ident 心跳经 Redis + (edge→center
  /v1/n9e/target-update)。

  - 告警判定到通知：alertRuleCache 规则 → eval 每规则 cron 查数据源产 AnomalyPoint → process.Handle 构建事件 + 规则级 pipeline + mute.IsMuted + pending/inhibit/fire 限流 → queue.EventQueue(10M) → dispatch.Consumer
  消费(持久化事件 + HandleEventNotify 双路派发：NotifyRule 路径 / 老式 Sender+回调+webhook+ibex 自愈) → sender 各渠道发送 → NotifyRecordQueue(1M) → DB。

  - 配置同步：DB → memsto(9s) / dscache(2s) 内存缓存；edge 通过 center HTTP API 拉取；edge 产生的事件/通知记录经 HTTP 回写 center。
